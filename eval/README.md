# 离线 Mock 评测

在仓库根目录用已安装项目依赖的 Python 环境运行。

```powershell
.\.venv\Scripts\python.exe -m eval.run_eval
```

默认读取 [manifest.csv](manifest.csv)，将逐场景结果写入本地 `eval/reports/latest.json`。可用 `--manifest` 指定临时清单，用 `--output` 指定报告文件。清单中的 PDF 路径以仓库根为基准，指向 `data/synthetic/resumes/` 下的合成 PDF。

| 退出码 | 含义 |
| --- | --- |
| `0` | 每个场景都符合标注。 |
| `1` | 至少一个场景与标注不符或执行异常。报告列出场景编号和差异字段，或异常类型。 |
| `2` | 清单、依赖或报告写入有误。 |

## v1 基线

13 个场景复用 10 份合成 PDF。每份 PDF 跑一次默认配置，另外用 S001 验证空岗位、项目回调返回空值和项目分越界。预期有 6 个 `SCORED`、7 个 `REVIEW`。人工复核的 `-1` 和无匹配岗位的 `0` 只要符合标注，都计为通过。

报告记录清单 SHA-256、样本和场景计数、逐条期望与实测字段以及偏差。报告仅包含场景编号、路由、分数、状态、原因码和必要的诊断类型。默认报告目录由 Git 忽略。

## 适用范围

- 这批结果衡量当前英文合成 PDF 和离线 Mock 规则的回归表现。真实模型项目分需要用人工标注的项目证据另行评估。
- 英文简历的学历可能抽为「未知」，教育日期也可能计入工龄。例如 S007 当前得到约 4.9 年，匹配 JD1。英文否定语句没有触发中文否定规则，S010 可能仍抽到 Docker。
- 英文 S001 PDF 的预期是 `JD1 / 60`，中文 S001 文本的 `JD2 / 52` 由评分和校验单测覆盖。

## 项目分标注

[project_score_cases.jsonl](project_score_cases.jsonl) 保存 12 条合成项目片段的固定标注。岗位相关性、个人贡献和结果证据分别取 `0、3、7、10`，三项之和为项目分，满分 30。

| 维度 | 0 | 3 | 7 | 10 |
| --- | --- | --- | --- | --- |
| 岗位相关性 | 无相关证据 | 仅有领域或工具 | 有对应岗位的具体任务 | 多项对应任务且有实现细节 |
| 个人贡献 | 未说明本人参与 | 明确参与但未说明职责 | 说明具体职责或行动 | 给出本人技术决策、取舍及负责范围 |
| 结果证据 | 无结果 | 仅声称完成或改善 | 有可描述的交付、验证或团队结果 | 有具体可追溯的验收方式或前后对比 |

非零分需要可在项目片段中找到的非空引证。空片段直接得 0 分。有片段时，客户端返回结构化 JSON，适配层校验并求和。假客户端单测验证数据合同和复核流程。现有 PDF 评测和项目分标注各自维护。

下面第一条只列出会试跑的固定场景。第二条显式启用真实调用，会产生 API 用量。入口只读取冻结标注中的 `full_30`、`tools_only`、`jailbreak_tools` 三条合成片段和对应岗位要求。

本地报告为 `eval/reports/deepseek-smoke.json`。有效响应与人工标注完全一致时退出 `0`，有响应失败或标注差异时退出 `1`，配置或写报告出错时退出 `2`。报告里的费用按 [DeepSeek 官方峰时未命中缓存价](https://api-docs.deepseek.com/quick_start/pricing/) 和返回的可计量 token 估算，账单金额以控制台为准。

首轮共有 3 次请求，三项分值均与标注一致，三条总分依次是 `30、3、3`。这是冒烟结果，完整标注集和真实招聘场景的表现仍需单独评估。

## DeepSeek 完整评测

追加 `--all` 预览全部 12 条标注。预览不读密钥。追加 `--live --all` 会发送实际请求，报告保存在 `eval/reports/deepseek-all.json`。

空片段记为 `SKIPPED`，三项和总分均为 0。其余 11 条各保留一次首发，整轮最多 2 次重试、13 次请求。非法回包单独记录，后续样本继续运行。完整模式退出 `0` 表示清单已跑完，退出 `1` 表示因全局错误提前中止，退出 `2` 表示配置、清单或写报告出错。
