# 踩坑记录

## [2026-11-21] 审核评论混入历史规划样本（PR #33）
- **现象**：APPROVED 的描述将 RV009 年限、RV010–RV012 场景及岗位路径写错，不能直接作为标签复审证据。
- **根因**：审核者确认评论混入历史规划的负例，没有逐项对应当前 head 的 query。
- **解决方法**：按 head 与数据 SHA 对照原文，更正补审见 [评论](https://github.com/yjy18312446491/agent_development/pull/33#issuecomment-7056976801)；独立冻结复审记录，测试见 `tests/test_retrieval_eval.py`。
- **防呆约定**：核对实际文本、完整 head 和数据 SHA；修正审查证据，不为迎合错误评论改标签，过时评论不得作为最终审批依据。

## [2026-11-21] frozen 数据类不保证嵌套列表不可变
- **现象**：岗位的 skills 列表仍能在内存修改；程序调用方替换标签或复审信息后也可能携带旧 SHA。
- **根因**：不可变数据类只约束属性赋值，不能证明载入后的整体输入仍与复审快照相同。
- **解决方法**：加载时记录岗位、查询、标签、依据及复审信息的输入指纹，评测前重新核对；补充变更标签、文本、复审链接和嵌套列表的回归测试。
- **防呆约定**：不能仅凭对象上的旧 SHA 声称新输入已经审核；快照不一致时在提供器构造前拒绝。
