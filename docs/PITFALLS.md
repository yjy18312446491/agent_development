# 踩坑记录

## [2026-11-21] 清空环境和 pip isolated 仍回退注册表代理（PR #40）
- **现象**：新 venv 的 pip 21.2.4 安装退出 2，`check_hostname requires server_hostname`；A 停止，B 未运行。
- **根因**：Requests 仍发现 Windows 注册表的 IP 形式 HTTPS 代理；urllib3 1.26.6 省略 IP 的 hostname，与代理 context 的主机名校验冲突。
- **处理提案（待审未实施）**：确认既有端口支持 HTTP CONNECT 后，仅对新安装进程注入现有 HTTP 项；不升级包或修改系统代理，未确认则不重试。
- **防呆约定**：isolated 不等于禁用系统代理；先只读核对来源/协议，保留失败现场，新 head 补审和重新授权后才能单轮重试。

## [2026-11-21] 审核评论混入历史规划样本（PR #33）
- **现象**：APPROVED 的描述将 RV009 年限、RV010–RV012 场景及岗位路径写错，不能直接作为标签复审证据。
- **根因**：审核者确认评论混入历史规划的负例，没有逐项对应当前 head 的 query。
- **解决方法**：按 head 与数据 SHA 对照原文，更正补审见 [评论](https://github.com/yjy18312446491/agent_development/pull/33#issuecomment-7056976801)；独立冻结复审记录，测试见 `tests/test_retrieval_eval.py`。
- **防呆约定**：核对实际文本、完整 head 和数据 SHA；修正审查证据，不为迎合错误评论改标签，过时评论不得作为最终审批依据。

## [2026-11-21] frozen 数据类不保证嵌套列表不可变
- **现象**：岗位的 skills 列表仍能在内存修改；程序调用方替换标签或复审信息后也可能携带旧 SHA。
- **根因**：不可变数据类只约束属性赋值，不能证明载入后的整体输入仍与复审快照相同。
- **解决方法**：加载时记录岗位、查询、标签、依据及复审信息的输入指纹，评测前重新核对；补充变更标签、文本、复审链接和嵌套列表的回归测试。
- **防呆约定**：不能仅凭对象上的旧 SHA 声称新输入已经审核；快照不一致时在提供器构造前拒绝。

## [2026-11-21] 凭证读取早于源码预检（PR #35）
- **现象**：Cursor 指出脏源码虽会拒绝发网，但仍先读取凭证；无需读取时触碰了配置。
- **根因**：main 在调用 `_source_commit()` 之前执行 `from_env_file()`。
- **解决方法**：源码预检提前；新增“源码失败时凭证读取必须未调用”的假配置测试，见 `test_invalid_source_is_rejected_before_any_credential_read`。
- **防呆约定**：先完成不依赖凭证的本地检查，再读取配置；只改顺序，不绕过锁和预算。

## [2026-11-21] 进程存在不等于服务就绪（PR #40）
- **现象**：B01 探针 connect 报 10013、Edge 拒绝连接，进程仍存活且日志为空。
- **根因**：探针传输层权限被拒绝；执行器日志退出后才落盘且未落实 60 秒就绪监督，服务具体阻塞点未确定。
- **修复提案**：新轮申请工具沙箱外回环执行，流式日志、所属监听及一次 health/status 构成就绪门；仅 B01，待审/授权，尚未实施。
- **防呆约定**：不可见/权限错误不能当端口空闲，不能仅凭 PID 或空日志判启动成功，不改防火墙/代理或重跑旧轮。
